200 ms of silence → model: 9% finished → keep waiting 700 ms → a fixed timer replies here and talks over the speaker sentence ends → model: 96% finished → reply after 200 ms

Viraam tells a voice agent whether the speaker has finished, or is only pausing.

Most agents wait for a fixed stretch of silence. Short waits interrupt people mid-thought; long waits feel slow. Viraam listens to how the speech sounds at each pause and answers in about 22 ms on one CPU core.

As an agent's turn-taking rule

406 unedited Hindi test recordings (FLEURS), pauses as recorded. “Cut off” means the agent replied before the speaker finished.

Faster and less interrupting than a 500 ms timer. It does not yet match the low cut-off rate of a 700 ms or longer timer; pauses at commas are the main cause.

One request per pause

Send the speech so far, up to the pause. Only the last 8 seconds are used. You get back the probability that the turn is complete.


      
from indic_eot import EndOfTurnDetector

detector = EndOfTurnDetector.load()

# audio: mono float32 at 16 kHz
p = detector.predict(audio)
if p >= 0.5:
    reply()          # the speaker is done
else:
    keep_listening() # only a pause

    

    
The model is 10 MB and needs only numpy and onnxruntime. Full reference: interactive API docs.

  


  

    
What it cannot do yet

    
    
      
  • It was trained on read Hindi speech from one corpus. Expect weaker results on casual conversation, other accents and other languages.
    • 
      
  • It judges the sound only. It does not read the words, so a pause after a clause that could stand alone is often called finished.
    • 
      
  • It has not been tested on recordings of people hesitating in real calls.
